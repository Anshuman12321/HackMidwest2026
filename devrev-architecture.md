# Ripple architecture — current references

The initial architecture draft is superseded by the outcome-led, source-grounded handoff:

- [Completed work, data inventory, mappings, UI paths, and integration plan](docs/data-and-integrations.md)
- [Agent build guide, contracts, skill starter, and acceptance checks](docs/agent-build-guide.md)
- [Interactive architecture site](https://ripple-demo-architecture.pearlyperch6.chatgpt.site/)

Start from the business outcome. Retrieve relevant DevRev evidence. Validate source IDs, dates, owners, citations, and coverage. Build a Context Bundle, then an Action Graph. Obtain approval for the exact proposed actions. Create or reuse scoped DevRev work and return native IDs.

The supported first demo is the Maple Payments Brazil renewal incident, not an invented company or an unverified six-month-old worker configuration decision. Native data is now imported; the custom agent and its write execution are planned. The site previews the workflow and does not make live DevRev writes.
